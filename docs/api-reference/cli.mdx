frac provides two CLI tools: the main `frac` CLI for development and production workflows, and `create-frac` for bootstrapping new projects.

## frac CLI

The main CLI is available as `frac` after installing `frac` in your project.

### frac dev

Start the development server with hot module reloading.

```bash
frac dev
```

- Starts a development server at `http://localhost:3000/`
- Exposes MCP server at `http://localhost:3000/mcp`
- Enables file watching with automatic server restart
- Enables Hot Module Reloading (HMR) for views

#### Flags

| Flag | Description |
|------|-------------|
| `-p, --port <number>` | Port to run the server on. Defaults to `3000`, or the next available port if `3000` is in use. |
| `--open` | Open the local app URL in your browser when the server is ready. |

You can also set the port via the `PORT` environment variable:

```bash
PORT=8080 frac dev
```

If you'd rather open the local app URL automatically, export `FRAC_OPEN=true` at the shell level (e.g. in your `~/.zshrc`, `~/.bashrc`, or shell profile). It's equivalent to passing `--open` on every run:

```bash
# one-off
FRAC_OPEN=true frac dev

# persistent (add to your shell profile)
export FRAC_OPEN=true
```

### frac build

Build your views and MCP server for production deployment.

```bash
frac build
```

**What it does:**

1. **Building views** - Compiles your React views using Vite
2. **Compiling server** - Transpiles TypeScript server code
3. **Copying static assets** - Moves built assets to the `dist/` directory

The output is placed in the `dist/` directory, ready for production deployment.

---

### frac start

Start the production server.

```bash
frac start
```

**Requirements:**
- Must run `frac build` first
- Requires `dist/server.js` to exist

**What it does:**
- Runs the compiled server from `dist/server.js`
- Sets `NODE_ENV=production`
- Serves the MCP endpoint at `http://localhost:3000/mcp`
- Serves pre-built view assets from `/assets`

## Fractal Cloud Commands

The main `frac` CLI also includes commands for authenticating with Fractal Cloud, deploying projects, opening project databases, and managing Cloud Storage.

### Environment

| Variable | Description |
|----------|-------------|
| `FRACTAL_API_URL` | Fractal backend URL. Defaults to `https://web-api.usefractal.dev`. |
| `FRACTAL_PROJECT_ID` | Fallback project ID when `frac.json` is not present. |

Project-aware commands resolve the project ID in this order:

1. `--project <id>`
2. nearest `frac.json`
3. `FRACTAL_PROJECT_ID`

`frac.json` should contain:

```json
{
  "projectId": "project_123"
}
```

### frac auth login

Log in with your Fractal account and store the session in macOS Keychain.

```bash
frac auth login
```

### frac auth status

Show the current login status.

```bash
frac auth status
```

### frac auth logout

Remove the stored session from macOS Keychain.

```bash
frac auth logout
```

### frac token

Print a scoped `FRACTAL_CLOUD_TOKEN`.

```bash
frac token
```

#### Flags

| Flag | Description |
|------|-------------|
| `--project <id>` | Project ID. Defaults to `frac.json`, then `FRACTAL_PROJECT_ID`. |
| `--env <dev\|prod>` | Cloud environment. Defaults to `dev`. |
| `--ttl <seconds>` | Token lifetime. Maximum `3600` seconds. |
| `--format <env\|raw\|json>` | Output format. Defaults to `env`. |

Examples:

```bash
frac token --project project_123 --env prod --ttl 3600
frac token --format raw
frac token --format json
```

### frac sql

Open a SQL shell for a project database.

```bash
frac sql
```

#### Flags

| Flag | Description |
|------|-------------|
| `--project <id>` | Project ID. Defaults to `frac.json`, then `FRACTAL_PROJECT_ID`. |
| `--env <dev\|prod>` | Cloud environment. Defaults to `dev`. |

Requires `psql` on your `PATH`.

### frac deploy

Deploy the current directory using `frac.json`.

```bash
frac deploy
```

#### Flags

| Flag | Description |
|------|-------------|
| `--project <id>` | Project ID. Defaults to `frac.json`, then `FRACTAL_PROJECT_ID`. |

The deploy command packages the current directory, respects `.gitignore` when run from a git worktree, excludes common secret and build paths, uploads the bundle to Fractal Cloud, and starts a deployment.

### frac cloud storage

Manage Fractal Cloud Storage.

```bash
frac cloud storage
```

#### Enable storage

```bash
frac cloud storage enable
```

#### List objects

```bash
frac cloud storage list --prefix uploads/
```

#### Upload an object

```bash
frac cloud storage put ./local.txt remote.txt
```

#### Download an object

```bash
frac cloud storage get remote.txt ./local.txt
```

Cloud Storage subcommands accept `--project`, `--env`, and `--ttl` where relevant.

## create-frac

A standalone CLI for bootstrapping new frac projects.

```bash
npm create @usefractal/frac@latest [directory]
```

Or with other package managers:

<CodeGroup>
```bash npm
npm create @usefractal/frac@latest
```
```bash pnpm
pnpm create @usefractal/frac@latest
```
```bash yarn
yarn create @usefractal/frac
```
```bash bun
bun create @usefractal/frac
```
</CodeGroup>

### Arguments

| Argument | Description |
|----------|-------------|
| `[directory]` | Target directory for the new project. If not specified, you'll be prompted to enter a project name. Use `.` to create in the current directory. |

### Options

| Option | Description |
|--------|-------------|
| `-h, --help` | Show help message |
| `--demo` | Scaffold the richer demo project |
| `--overwrite` | Remove existing files in target directory without prompting |
| `--pm <choice>` | Package manager to use: `bun`, `deno`, `npm`, `pnpm`, or `yarn` |
| `--skip-skills` | Skip installing coding agent skills |
| `--start` | Start the development server after scaffolding |
| `--yes` | Skip prompts and use defaults for unprovided options |

### Examples

**Create a new project interactively:**

```bash
npm create @usefractal/frac@latest
```

**Create a project in a specific directory:**

```bash
npm create @usefractal/frac@latest my-app
```

**Create in current directory, overwrite existing files, and start immediately:**

```bash
npm create @usefractal/frac@latest . --overwrite --start
```

### What it creates

The scaffolder copies a starter template that includes:

- `server/index.ts` - MCP server with example tools
- `web/` - React views with example components
- `package.json` - Pre-configured with all dependencies
- `tsconfig.json` files - TypeScript configuration
- `vite.config.ts` - Vite configuration for view bundling
- `nodemon.json` - File watching configuration for development

## Package Manager Scripts

When you create a new frac project, the `package.json` includes these scripts:

| Script | Command | Description |
|--------|---------|-------------|
| `dev` | `frac dev` | Start development server |
| `build` | `frac build` | Build for production |
| `start` | `frac start` | Start production server |

Run them with your package manager:

<CodeGroup>
```bash npm
npm run dev
npm run build
npm start
```
```bash pnpm
pnpm dev
pnpm build
pnpm start
```
```bash yarn
yarn dev
yarn build
yarn start
```
```bash bun
bun dev
bun build
bun start
```
```bash deno
deno task dev
deno task build
deno task start
```
</CodeGroup>
